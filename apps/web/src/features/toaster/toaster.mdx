# Toaster

Глобальная система уведомлений: очередь тостов, их позиционирование, таймеры
автозакрытия и пауза при наведении. Показать уведомление можно из любого места —
через `useToaster().notify(...)`.

Сам тост-карточку рисует примитив [`Toast`](?path=/docs/shared-components-toast--docs);
Toaster отвечает за всё вокруг: стек, порядок, тайминги, доступность контейнера.

---

## Архитектура

- **`ToasterProvider`** — владеет очередью (`useToasterQueue`), отдаёт `notify`/`dismiss`
  через контекст и порталит стек в `document.body` (поверх всего, `--z-toast`).
- **`useToaster()`** — доступ к `notify`/`dismiss` из компонентов (консоль, будущие формы CMS).
- **`ToasterView`** (презентационный, ниже) — стек тостов; всё состояние приходит пропами.

Автозакрытие ведётся на JS-таймерах (а не на CSS-анимации полосы), поэтому работает
и при `prefers-reduced-motion`, и детерминированно тестируется.

## Живой поток

Кнопки вызывают `notify` — тосты сами встают в стек, отсчитывают время и уходят.
Новые вытесняют старейшие (не больше четырёх на экране).

# Когда использовать

- краткий неблокирующий отклик на действие (сохранено, скопировано, ошибка запроса);
- команда консоли `notify`.

# Когда **не** использовать

- критический выбор, требующий решения, — модальное окно;
- постоянный статус формы — сообщение поля.

---

## Доступность

- Контейнер — `role="region"` с именем (`Уведомления`); объявление содержимого берёт
  на себя каждый `Toast` (`status`/`alert`), поэтому `aria-live` не дублируется.
- Наведение **и фокус** внутри стека ставят автозакрытие на паузу — читатель успевает
  дочитать и добраться до крестика с клавиатуры.
- Пустой стек не рендерит контейнер.

## Токены

`--z-toast` (слой), `--navbar-height` (отступ сверху); локальные custom properties
`--toaster-inset/gap/width/exit` — тюнинг стека.

## Связанные компоненты

- [`Toast`](?path=/docs/shared-components-toast--docs) — карточка одного уведомления.
